# ADR-001: Go as implementation language

## Status

Accepted (Phase 0)

## Context

Need a long-running cross-platform daemon that talks to Docker Engine API, serves a web UI, and ships as a self-contained executable on Windows, Linux, and macOS.

## Decision

Implement the backend (and process host for the embedded UI) in Go.

## Alternatives

- Rust — viable single binary, weaker day-to-day Docker SDK ergonomics for this team
- Node.js / Python — poor fit for single-binary distribution and long-lived collectors
- PowerShell 7 — cross-platform, but wrong runtime for an HTTP/WebSocket service

## Why

Best practical combination of official Docker client support, easy cross-compilation (`CGO_ENABLED=0`), concurrency, and small operational footprint.

## Consequences

Contributors need Go familiarity. Frontend remains TypeScript/React.
